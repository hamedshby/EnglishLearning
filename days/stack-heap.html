Stack & Heap in .NET

آشنایی با مفاهیم Stack و Heap در .NET، تفاوت value type و reference type و ارتباط آن‌ها با Garbage Collection

01

Podcast Transcript & Translation

متن پادکست همراه با ترجمه فارسی

Hello.

سلام.

In this episode, we’re going to talk about two important memory concepts in .NET: Stack and Heap.

در این قسمت می‌خواهیم درباره دو مفهوم مهم مدیریت حافظه در .NET صحبت کنیم: Stack و Heap.

If you work with C#, you often hear statements like:

اگر با C# کار می‌کنید، احتمالاً جمله‌هایی مثل این‌ها را زیاد شنیده‌اید:

“Value types are stored on the Stack.”

«value typeها روی Stack ذخیره می‌شوند.»

“Objects are stored on the Heap.”

«objectها روی Heap ذخیره می‌شوند.»

These statements are useful as a starting point, but the real picture is a little more interesting.

این جمله‌ها به‌عنوان نقطه شروع مفید هستند، اما تصویر واقعی کمی جالب‌تر است.

So, what are the Stack and the Heap?

پس Stack و Heap دقیقاً چه هستند؟

Let’s start with the Stack.

بیایید از Stack شروع کنیم.

The Stack is a region of memory that is mainly used for method execution.

Stack ناحیه‌ای از حافظه است که عمدتاً برای اجرای methodها استفاده می‌شود.

Every time a method is called, .NET creates something called a stack frame.

هر بار که یک method فراخوانی می‌شود، .NET چیزی به نام stack frame ایجاد می‌کند.

That frame can contain things such as local variables, method parameters, and information needed to return to the calling method.

آن frame می‌تواند شامل مواردی مانند local variableها، method parameterها و اطلاعات لازم برای بازگشت به method فراخواننده باشد.

For example:

برای مثال:

void Calculate()
{
    int number = 10;
    int result = number * 2;
}

Variables like number and result are simple local values, and they are typically associated with the current stack frame.

متغیرهایی مانند number و result مقادیر ساده local هستند و معمولاً به stack frame فعلی مرتبط‌اند.

When the method finishes, that stack frame is removed automatically.

وقتی method به پایان می‌رسد، آن stack frame به‌طور خودکار حذف می‌شود.

This makes stack allocation very fast.

همین موضوع باعث می‌شود stack allocation بسیار سریع باشد.

Now let’s talk about the Heap.

حالا بیایید درباره Heap صحبت کنیم.

The Heap is used for dynamically allocated objects.

Heap برای objectهایی استفاده می‌شود که به‌صورت پویا (dynamically) allocate می‌شوند.

For example:

برای مثال:

var customer = new Customer();

When we create a new object like this, the Customer object is normally allocated on the managed Heap.

وقتی object جدیدی مثل این می‌سازیم، object Customer معمولاً روی managed Heap allocate می‌شود.

But there is an important detail.

اما یک نکته مهم وجود دارد.

The variable customer does not contain the entire object.

متغیر customer کل object را در خود ندارد.

It contains a reference to that object.

آن یک reference به آن object را در خود دارد.

You can think of the reference as an address or a way to locate the object in memory.

می‌توانید reference را مانند یک آدرس یا راهی برای پیدا کردن object در حافظه در نظر بگیرید.

So we may have a reference associated with the current method execution, while the actual object lives on the Heap.

پس ممکن است یک reference مرتبط با اجرای method فعلی داشته باشیم، در حالی که خود object روی Heap قرار دارد.

This difference becomes important when we compare value types and reference types.

این تفاوت زمانی اهمیت پیدا می‌کند که value typeها و reference typeها را با هم مقایسه کنیم.

Types such as: int, bool, double, and most struct types are value types.

typeهایی مانند int، bool، double و بیشتر typeهای struct، value type هستند.

Classes, arrays, strings, and delegates are reference types.

classها، arrayها، stringها و delegateها، reference type هستند.

But saying that value types always live on the Stack is not completely correct.

اما گفتن اینکه value typeها همیشه روی Stack قرار دارند، کاملاً درست نیست.

A value type can also exist inside an object on the Heap.

یک value type می‌تواند داخل یک object روی Heap هم وجود داشته باشد.

For example:

برای مثال:

public class Product
{
    public decimal Price { get; set; }
}

decimal is a value type.

decimal یک value type است.

But because Price is part of a Product object, its value is stored as part of that object on the Heap.

اما چون Price بخشی از object Product است، مقدار آن به‌عنوان بخشی از آن object روی Heap ذخیره می‌شود.

So the important idea is not simply: “Value type equals Stack.”

پس ایده مهم این نیست که به‌سادگی بگوییم: «value type یعنی Stack.»

It is better to understand where the value belongs and how it is allocated.

بهتر است بفهمیم آن مقدار به کجا تعلق دارد و چگونه allocate می‌شود.

Another major difference between Stack and Heap is memory management.

یک تفاوت مهم دیگر بین Stack و Heap، مدیریت حافظه است.

Stack memory is released automatically when methods return.

حافظه Stack هنگام بازگشت methodها به‌طور خودکار آزاد می‌شود.

Heap memory is managed by the Garbage Collector, or GC.

حافظه Heap توسط Garbage Collector یا GC مدیریت می‌شود.

Suppose we write:

فرض کنید بنویسیم:

var order = new Order();

Later, if nothing in the application can reach that Order object anymore, it becomes eligible for garbage collection.

بعداً، اگر هیچ بخشی از application دیگر نتواند به آن object Order دسترسی پیدا کند، آن object برای garbage collection واجد شرایط می‌شود.

The Garbage Collector can eventually reclaim that memory.

Garbage Collector در نهایت می‌تواند آن حافظه را پس بگیرد.

This is one of the major advantages of managed environments like .NET.

این یکی از مزیت‌های بزرگ محیط‌های managed مانند .NET است.

As developers, we usually don’t manually free managed objects.

ما به‌عنوان توسعه‌دهنده معمولاً managed objectها را به‌صورت دستی آزاد نمی‌کنیم.

The runtime handles most of that work for us.

runtime بیشتر آن کار را برای ما انجام می‌دهد.

However, understanding Stack and Heap is still very useful.

با این حال، درک Stack و Heap همچنان بسیار مفید است.

It helps us understand object lifetime, references, garbage collection, allocations, performance, and why certain pieces of code behave differently.

این درک به ما کمک می‌کند object lifetime، referenceها، garbage collection، allocationها، performance و دلیل رفتار متفاوت برخی کدها را بهتر بفهمیم.

For example, if an application creates millions of temporary objects, it can create pressure on the Heap and increase the amount of work the Garbage Collector needs to do.

برای مثال، اگر یک application میلیون‌ها object موقت بسازد، می‌تواند روی Heap فشار ایجاد کند و مقدار کاری که Garbage Collector باید انجام دهد را افزایش دهد.

That can affect performance.

این موضوع می‌تواند روی performance تأثیر بگذارد.

On the other hand, stack-based memory is usually very fast and has a very predictable lifetime.

از طرف دیگر، حافظه مبتنی بر stack معمولاً بسیار سریع است و lifetime بسیار قابل‌پیش‌بینی دارد.

So, if we want to summarize everything:

پس اگر بخواهیم همه‌چیز را خلاصه کنیم:

The Stack is mainly connected to method execution and short-lived data, while the Heap is mainly used for dynamically allocated objects whose lifetime can extend beyond a single method call.

Stack عمدتاً به اجرای method و دادهٔ کوتاه‌عمر مرتبط است، در حالی که Heap عمدتاً برای objectهایی استفاده می‌شود که به‌صورت پویا allocate می‌شوند و lifetime آن‌ها می‌تواند از یک method call فراتر برود.

And one final point is very important:

و یک نکته پایانی بسیار مهم است:

Don’t memorize the rule: “Value types are on the Stack and reference types are on the Heap.”

این قاعده را حفظ نکنید: «value typeها روی Stack و reference typeها روی Heap هستند.»

Instead, understand the bigger picture.

در عوض، تصویر بزرگ‌تر را درک کنید.

In .NET, memory depends on context, allocation, object layout, and how values are used.

در .NET، حافظه به context، allocation، object layout و نحوه استفاده از مقادیر بستگی دارد.

Once you understand Stack and Heap properly, concepts like reference types, value types, object lifetime, and Garbage Collection become much easier to understand.

وقتی Stack و Heap را درست درک کنید، مفاهیمی مانند reference type، value type، object lifetime و Garbage Collection بسیار قابل‌فهم‌تر می‌شوند.

And that is why Stack and Heap are such important foundations for every .NET developer.

و به همین دلیل است که Stack و Heap برای هر توسعه‌دهنده .NET، پایه‌های بسیار مهمی محسوب می‌شوند.
