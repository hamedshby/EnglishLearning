Composition

آشنایی با Composition، ساخت objectهای پیچیده از objectهای کوچک‌تر و ایجاد designی انعطاف‌پذیر در .NET

01

Podcast Transcript & Translation

متن پادکست همراه با ترجمه فارسی

Hello.

سلام.

In this episode, we’re going to talk about an important Object-Oriented Programming concept called Composition.

در این قسمت می‌خواهیم درباره یک concept مهم در Object-Oriented Programming به نام Composition صحبت کنیم.

Composition is a way of building complex objects by combining smaller objects together.

Composition روشی برای ساخت objectهای پیچیده از طریق ترکیب objectهای کوچک‌تر است.

The main idea is simple:

ایده اصلی ساده است:

Instead of saying “is-a,” Composition usually represents a “has-a” relationship.

به‌جای بیان relationship از نوع «is-a»، Composition معمولاً یک relationship از نوع «has-a» را نشان می‌دهد.

Let’s look at an example.

بیایید یک مثال را بررسی کنیم.

Imagine we have a Car class.

تصور کنید یک class به نام Car داریم.

A car has an engine.

یک خودرو یک موتور دارد.

So instead of making Car inherit from Engine, we create an Engine object inside the Car.

بنابراین به‌جای اینکه Car از Engine ارث‌بری کند، یک object از نوع Engine درون Car می‌سازیم.

For example:

برای مثال:

public class Engine
{
    public void Start()
    {
        Console.WriteLine("Engine started.");
    }
}

And then:

و سپس:

public class Car
{
    private readonly Engine _engine;

    public Car(Engine engine)
    {
        _engine = engine;
    }

    public void Start()
    {
        _engine.Start();
        Console.WriteLine("Car is ready to move.");
    }
}

Here, the Car does not inherit from Engine.

در اینجا Car از Engine ارث‌بری نمی‌کند.

Instead, it uses an Engine.

در عوض، از یک Engine استفاده می‌کند.

That is Composition.

این همان Composition است.

This approach is very common in modern .NET applications.

این رویکرد در applicationهای مدرن .NET بسیار رایج است.

And one of the biggest advantages of Composition is flexibility.

و یکی از بزرگ‌ترین مزیت‌های Composition، flexibility است.

Imagine that later we have different engine types.

تصور کنید بعداً typeهای مختلفی از موتور داشته باشیم.

For example:

برای مثال:

public interface IEngine
{
    void Start();
}

Then we can create different implementations:

سپس می‌توانیم implementationهای مختلفی ایجاد کنیم:

public class GasEngine : IEngine
{
    public void Start()
    {
        Console.WriteLine("Gas engine started.");
    }
}

And:

و:

public class ElectricEngine : IEngine
{
    public void Start()
    {
        Console.WriteLine("Electric motor started.");
    }
}

Now our Car can depend on the abstraction:

حالا Car ما می‌تواند به abstraction وابسته باشد:

public class Car
{
    private readonly IEngine _engine;

    public Car(IEngine engine)
    {
        _engine = engine;
    }

    public void Start()
    {
        _engine.Start();
    }
}

This means we can give the car a gas engine or an electric engine without changing the Car class itself.

این یعنی می‌توانیم بدون تغییر خود class به نام Car، یک موتور بنزینی یا الکتریکی به آن بدهیم.

That makes the design much easier to extend.

این کار گسترش design را بسیار آسان‌تر می‌کند.

Composition is also closely related to Dependency Injection.

Composition ارتباط نزدیکی نیز با Dependency Injection دارد.

In ASP.NET Core, we often inject services into other services.

در ASP.NET Core، ما اغلب serviceها را به serviceهای دیگر inject می‌کنیم.

For example, an OrderService may use a payment service, a notification service, and a repository.

برای مثال، یک OrderService ممکن است از payment service، notification service و repository استفاده کند.

The OrderService does not inherit from any of them.

OrderService از هیچ‌کدام از آن‌ها ارث‌بری نمی‌کند.

It simply uses them.

فقط از آن‌ها استفاده می‌کند.

That is Composition.

این همان Composition است.

For example:

برای مثال:

public class OrderService
{
    private readonly IPaymentService _paymentService;
    private readonly INotificationService _notificationService;

    public OrderService(
        IPaymentService paymentService,
        INotificationService notificationService)
    {
        _paymentService = paymentService;
        _notificationService = notificationService;
    }
}

This design gives us another major benefit:

این design مزیت مهم دیگری به ما می‌دهد:

low coupling.

low coupling.

Each class focuses on its own responsibility and collaborates with other objects to complete more complex tasks.

هر class بر responsibility خودش تمرکز می‌کند و برای انجام taskهای پیچیده‌تر با objectهای دیگر همکاری می‌کند.

Composition is often compared with Inheritance.

Composition اغلب با Inheritance مقایسه می‌شود.

Inheritance is useful when there is a true is-a relationship.

Inheritance زمانی مفید است که یک is-a relationship واقعی وجود داشته باشد.

For example:

برای مثال:

A Developer is an Employee.

یک Developer، Employee است.

But if one object simply needs another object to do its job, Composition is usually a better choice.

اما اگر یک object فقط برای انجام کارش به object دیگری نیاز دارد، Composition معمولاً انتخاب بهتری است.

This is why you may hear the famous software design principle:

به همین دلیل ممکن است این software design principle مشهور را بشنوید:

Favor Composition over Inheritance.

Composition را به Inheritance ترجیح دهید.

It doesn’t mean inheritance is bad.

این جمله به این معنا نیست که Inheritance بد است.

It means we should not create inheritance hierarchies when simple object collaboration can give us a cleaner and more flexible design.

یعنی زمانی که همکاری ساده objectها designی تمیزتر و انعطاف‌پذیرتر به ما می‌دهد، نباید inheritance hierarchy بسازیم.

So, if we want to summarize Composition in one sentence:

پس اگر بخواهیم Composition را در یک جمله خلاصه کنیم:

Composition means building objects by combining other objects and delegating responsibilities to them.

Composition یعنی ساخت objectها از طریق ترکیب objectهای دیگر و delegate کردن responsibilityها به آن‌ها.

In real .NET applications, Composition is everywhere.

در applicationهای واقعی .NET، Composition همه‌جا دیده می‌شود.

You see it in Dependency Injection, service design, Clean Architecture, Domain-Driven Design, and many common design patterns.

آن را در Dependency Injection، service design، Clean Architecture، Domain-Driven Design و بسیاری از design patternهای رایج می‌بینید.

And when used correctly, Composition can make your code more flexible, testable, maintainable, and easier to change.

و زمانی که Composition به‌درستی استفاده شود، می‌تواند کد را انعطاف‌پذیرتر، testableتر، maintainableتر و تغییر آن را آسان‌تر کند.

That is the real power of Composition in .NET.

این قدرت واقعی Composition در .NET است.
