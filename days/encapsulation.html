Encapsulation in .NET

آشنایی با Encapsulation، کنترل دسترسی به state داخلی object و پیاده‌سازی business ruleها در C# و .NET

01

Podcast Transcript & Translation

متن پادکست همراه با ترجمه فارسی

Hello.

سلام.

In this episode, we’re going to talk about one of the four main principles of Object-Oriented Programming: Encapsulation.

در این قسمت می‌خواهیم درباره یکی از چهار اصل اصلی Object-Oriented Programming صحبت کنیم: Encapsulation.

Encapsulation is a very important concept in C# and .NET because it helps us protect the internal state of our objects and control how other parts of the application interact with them.

Encapsulation مفهومی بسیار مهم در C# و .NET است، زیرا کمک می‌کند state داخلی objectهای خود را محافظت و نحوه تعامل بخش‌های دیگر برنامه با آن‌ها را کنترل کنیم.

So, what exactly is Encapsulation?

پس Encapsulation دقیقاً چیست؟

In simple terms, Encapsulation means keeping data and behavior together inside a class and controlling access to that data.

به زبان ساده، Encapsulation یعنی داده و behavior را درون یک class کنار هم نگه داریم و دسترسی به آن داده را کنترل کنیم.

Let’s look at a simple example.

بیایید یک مثال ساده را بررسی کنیم.

Imagine we have a BankAccount class.

تصور کنید یک class به نام BankAccount داریم.

A bank account has a balance.

یک حساب بانکی دارای balance است.

A simple implementation might look like this:

یک implementation ساده می‌تواند به این شکل باشد:

public class BankAccount
{
    public decimal Balance { get; set; }
}

At first, this looks completely fine.

در نگاه اول، این کد کاملاً مناسب به نظر می‌رسد.

But there is a problem.

اما یک مشکل وجود دارد.

Because the Balance property has a public setter, any part of the application can change it directly.

چون property به نام Balance یک setter از نوع public دارد، هر بخشی از برنامه می‌تواند مقدار آن را مستقیماً تغییر دهد.

For example:

برای مثال:

account.Balance = -5000;

Now we have a negative balance, even though our business rules may not allow this.

اکنون یک balance منفی داریم، با اینکه ممکن است business ruleهای ما چنین وضعیتی را مجاز ندانند.

This is where Encapsulation becomes useful.

اینجاست که Encapsulation مفید واقع می‌شود.

Instead of allowing everyone to change the balance directly, we can protect it.

به‌جای اینکه به همه اجازه دهیم balance را مستقیماً تغییر دهند، می‌توانیم از آن محافظت کنیم.

For example:

برای مثال:

public class BankAccount
{
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive.");

        Balance += amount;
    }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentException("Amount must be positive.");

        if (amount > Balance)
            throw new InvalidOperationException("Insufficient balance.");

        Balance -= amount;
    }
}

Now, other parts of the application can read the balance, but they cannot change it directly.

اکنون بخش‌های دیگر برنامه می‌توانند balance را بخوانند، اما نمی‌توانند آن را مستقیماً تغییر دهند.

The only way to modify the balance is through the Deposit or Withdraw methods.

تنها راه تغییر balance، استفاده از methodهای Deposit یا Withdraw است.

And those methods contain the business rules that protect the object from invalid states.

این methodها business ruleهایی را در خود دارند که object را در برابر stateهای نامعتبر محافظت می‌کنند.

This is the main idea behind Encapsulation.

این ایده اصلی Encapsulation است.

Instead of exposing the internal state of an object, we expose controlled operations.

به‌جای آشکار کردن state داخلی یک object، operationهای کنترل‌شده را در اختیار دیگران قرار می‌دهیم.

In C#, Encapsulation is commonly implemented using access modifiers such as private, public, protected, and internal.

در C#، Encapsulation معمولاً با استفاده از access modifierهایی مانند private، public، protected و internal پیاده‌سازی می‌شود.

For example, a private field or method can only be accessed from inside its own class.

برای مثال، یک field یا method از نوع private فقط از داخل class خودش قابل دسترسی است.

A public member can be accessed from anywhere.

یک member از نوع public از همه‌جا قابل دسترسی است.

And a property with a private set allows other classes to read its value but prevents them from changing it directly.

همچنین property دارای private set به classهای دیگر اجازه می‌دهد مقدارش را بخوانند، اما از تغییر مستقیم آن جلوگیری می‌کند.

Encapsulation gives us several important benefits.

Encapsulation چند مزیت مهم در اختیار ما قرار می‌دهد.

First, it protects the internal state of an object.

اول، از state داخلی یک object محافظت می‌کند.

Second, it keeps business rules in one place.

دوم، business ruleها را در یک محل نگه می‌دارد.

Third, it reduces dependencies between different parts of the application.

سوم، dependency میان بخش‌های مختلف برنامه را کاهش می‌دهد.

And finally, it makes our code easier to maintain and change.

و در نهایت، نگهداری و تغییر کد را آسان‌تر می‌کند.

For example, if we later change how the balance is calculated, other parts of the application do not need to know about that implementation detail.

برای مثال، اگر بعداً روش محاسبه balance را تغییر دهیم، بخش‌های دیگر برنامه نیازی ندارند از آن implementation detail باخبر باشند.

They only need to use methods like Deposit and Withdraw.

آن‌ها فقط باید از methodهایی مانند Deposit و Withdraw استفاده کنند.

So, if we want to summarize Encapsulation in one sentence:

پس اگر بخواهیم Encapsulation را در یک جمله خلاصه کنیم:

Encapsulation means protecting the internal state of an object and allowing access to it only through controlled operations.

Encapsulation یعنی از state داخلی یک object محافظت کنیم و دسترسی به آن را فقط از طریق operationهای کنترل‌شده امکان‌پذیر سازیم.

In real .NET applications, especially when working with Domain-Driven Design, Clean Architecture, and rich domain models, Encapsulation is extremely important.

در برنامه‌های واقعی .NET، به‌ویژه هنگام کار با Domain-Driven Design، Clean Architecture و rich domain model، Encapsulation اهمیت بسیار زیادی دارد.

A well-designed class should not just store data.

یک class با طراحی مناسب نباید فقط داده ذخیره کند.

It should also protect its own rules and make it difficult to create an invalid state.

بلکه باید از ruleهای خودش نیز محافظت کند و ساختن یک state نامعتبر را دشوار سازد.

And that is the real power of Encapsulation in Object-Oriented Programming.

و این قدرت واقعی Encapsulation در Object-Oriented Programming است.
