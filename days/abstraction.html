Podcast Transcript & Translation

متن پادکست همراه با ترجمه فارسی

Hello.

سلام.

In this episode, we’re going to talk about another important principle of Object-Oriented Programming: Abstraction.

در این قسمت می‌خواهیم درباره یکی دیگر از principleهای مهم Object-Oriented Programming صحبت کنیم: Abstraction.

Abstraction is one of those concepts that sounds complicated at first, but we actually use it all the time in everyday life.

Abstraction از آن conceptهایی است که در ابتدا پیچیده به نظر می‌رسد، اما در زندگی روزمره همیشه از آن استفاده می‌کنیم.

Think about driving a car.

رانندگی با یک خودرو را تصور کنید.

When you press the brake pedal, you don’t need to understand exactly how the hydraulic system works.

وقتی پدال ترمز را فشار می‌دهید، لازم نیست دقیقاً بدانید سیستم هیدرولیک چگونه کار می‌کند.

When you turn the steering wheel, you don’t need to know every mechanical detail inside the steering system.

وقتی فرمان را می‌چرخانید، لازم نیست تمام جزئیات مکانیکی داخل سیستم فرمان را بدانید.

You only interact with the parts you need.

شما فقط با بخش‌هایی تعامل دارید که به آن‌ها نیاز دارید.

The complexity is hidden from you.

پیچیدگی از شما پنهان شده است.

That is the basic idea behind Abstraction.

این همان ایده اصلی Abstraction است.

In software development, Abstraction means hiding unnecessary implementation details and exposing only the behavior that other parts of the application need to use.

در software development، Abstraction یعنی پنهان‌کردن جزئیات غیرضروری implementation و نمایش فقط رفتاری که بخش‌های دیگر application به آن نیاز دارند.

Let’s look at a simple .NET example.

بیایید یک مثال ساده در .NET را بررسی کنیم.

Imagine we are building a payment system.

تصور کنید در حال ساختن یک سیستم پرداخت هستیم.

We may have different payment providers, but the rest of the application should not care about the internal details of each provider.

ممکن است payment providerهای مختلفی داشته باشیم، اما بقیه application نباید درگیر جزئیات داخلی هر provider شود.

We can create an interface:

می‌توانیم یک interface ایجاد کنیم:

public interface IPaymentService
{
    Task PayAsync(decimal amount);
}

Now we can create an implementation:

حالا می‌توانیم یک implementation بسازیم:

public class CreditCardPaymentService : IPaymentService
{
    public async Task PayAsync(decimal amount)
    {
        // Validate card

        // Connect to payment gateway

        // Send payment request

        // Process response
    }
}

The important point is that the code using IPaymentService does not need to know how the payment is processed.

نکته مهم این است که کدی که از IPaymentService استفاده می‌کند، لازم نیست بداند پرداخت چگونه پردازش می‌شود.

It simply calls:

آن فقط این method را فراخوانی می‌کند:

await paymentService.PayAsync(100);

The complicated details are hidden behind the abstraction.

جزئیات پیچیده پشت آن abstraction پنهان شده‌اند.

This gives us a very important advantage.

این کار یک مزیت بسیار مهم به ما می‌دهد.

We can change the implementation without changing the code that uses it.

می‌توانیم implementation را بدون تغییر کدی که از آن استفاده می‌کند، عوض کنیم.

For example, today we might use a credit card provider.

برای مثال، ممکن است امروز از یک provider کارت اعتباری استفاده کنیم.

Tomorrow, we could create another implementation:

فردا می‌توانیم implementation دیگری ایجاد کنیم:

public class BankPaymentService : IPaymentService
{
    public async Task PayAsync(decimal amount)
    {
        // Process payment through a bank
    }
}

The business logic can continue working with IPaymentService.

business logic می‌تواند همچنان با IPaymentService کار کند.

It doesn’t need to know which specific payment provider is being used.

لازم نیست بداند کدام payment provider مشخص در حال استفاده است.

In C#, Abstraction is commonly implemented using interfaces and abstract classes.

در C#، Abstraction معمولاً با استفاده از interfaceها و abstract classها پیاده‌سازی می‌شود.

An interface defines what an object can do.

یک interface مشخص می‌کند که یک object چه کاری می‌تواند انجام دهد.

An abstract class can define both common behavior and abstract behavior that derived classes must implement.

یک abstract class می‌تواند هم رفتار مشترک و هم رفتار abstractی را تعریف کند که derived classها باید پیاده‌سازی کنند.

For example:

برای مثال:

public abstract class NotificationService
{
    public abstract void Send(string message);
}

Then different implementations can provide their own behavior:

سپس implementationهای مختلف می‌توانند رفتار مخصوص خود را ارائه دهند:

public class EmailNotificationService : NotificationService
{
    public override void Send(string message)
    {
        Console.WriteLine("Sending email...");
    }
}

And another implementation might send an SMS.

و implementation دیگری ممکن است SMS ارسال کند.

This idea is everywhere in modern .NET development.

این ایده در همه‌جای .NET development مدرن دیده می‌شود.

When we use Dependency Injection, we usually inject abstractions such as interfaces instead of directly depending on concrete classes.

وقتی از Dependency Injection استفاده می‌کنیم، معمولاً به‌جای وابستگی مستقیم به concrete classها، abstractionهایی مانند interfaceها را inject می‌کنیم.

For example:

برای مثال:

public OrderService(IPaymentService paymentService)
{
}

OrderService doesn’t care how the payment system works internally.

OrderService اهمیتی نمی‌دهد که سیستم پرداخت در داخل چگونه کار می‌کند.

It only knows what operations are available through IPaymentService.

فقط می‌داند چه operationهایی از طریق IPaymentService در دسترس هستند.

This helps reduce coupling between different parts of the application.

این کار به کاهش coupling بین بخش‌های مختلف application کمک می‌کند.

It also makes the code easier to test, maintain, and extend.

همچنین test، نگهداری و گسترش کد را آسان‌تر می‌کند.

Abstraction is closely related to Encapsulation, but they are not exactly the same.

Abstraction ارتباط نزدیکی با Encapsulation دارد، اما این دو دقیقاً یکسان نیستند.

Encapsulation protects the internal state of an object.

Encapsulation از state داخلی یک object محافظت می‌کند.

Abstraction hides unnecessary complexity from the consumer.

Abstraction پیچیدگی غیرضروری را از consumer پنهان می‌کند.

So, if we want to summarize Abstraction in one sentence:

پس اگر بخواهیم Abstraction را در یک جمله خلاصه کنیم:

Abstraction means showing what an object can do while hiding the details of how it does it.

Abstraction یعنی نشان‌دادن اینکه یک object چه کاری می‌تواند انجام دهد، در حالی که جزئیات چگونگی انجام آن پنهان می‌شود.

And that is one of the reasons abstraction is so powerful in .NET.

و این یکی از دلایل قدرتمندبودن Abstraction در .NET است.

It allows us to build systems where different components communicate through clear contracts without needing to understand each other’s internal implementation.

Abstraction به ما اجازه می‌دهد سیستم‌هایی بسازیم که componentهای مختلف از طریق contractهای شفاف با هم ارتباط برقرار کنند، بدون اینکه لازم باشد implementation داخلی یکدیگر را بفهمند.

The result is software that is more flexible, easier to change, and much easier to maintain.

نتیجه، نرم‌افزاری است که انعطاف‌پذیرتر، تغییرپذیرتر و بسیار آسان‌تر قابل نگهداری است.

And that is the real power of Abstraction in Object-Oriented Programming.

و این قدرت واقعی Abstraction در Object-Oriented Programming است.
